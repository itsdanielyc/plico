# The miille family foundation: tokens, controls, chrome and dialogs

**Status** Accepted for the design branch

Plico follows the miille family contract in [docs/design/miille.md](../design/miille.md): a grey desk, a white sheet, black ink, with Onda as the reference. This record covers the foundation the window and the dialogs are drawn from. The shell's layout is a separate step.

Theme values live in `Theme/Tokens.axaml`, merged from `App.axaml`, with a light and a dark dictionary. The family brushes keep their shared names (`Base`, `Panel`, `Raised`, `Sunken`, `Hover`, `Pressed`, `Selected`, `Line`, `LineStrong`, `Fg`, `Fg2`, `Fg3`, `FgDisabled`, `OnFg`, the status pairs, `Scrim` and the graphite `Tile`), so the same words mean the same values in every miille app. Avalonia has no `color-mix`, so the hover and pressed mixes are resolved values. Plico adds `Desk` for the page canvas, `Paper`, and its meaning colours. Earlier keys that windows still use point at family values with `StaticResource`, and new code uses the family names. Radii, shadows, `InterFont` and `MonoFont` are tokens too. Before this, `InterFont` was referenced by every window but never defined.

Fluent supplies the control templates. Its accent colours, its neutral ramp and the state keys of every control Plico uses or might open are overridden in both dictionaries, so no system blue and no Fluent grey reaches a dialog. A scan of every colour resource the Fluent assembly defines, resolved in both themes, finds nothing outside the family status colours. Shared control classes live in `Theme/Controls.axaml`: buttons (primary, secondary, danger, ghost, icon, link), fields, keycaps, chips, plain lists, menus, callouts and the dialog parts.

Keyboard focus is an ink ring with a 2 px gap, drawn by `FocusRing` as the adorner layer's default focus adorner. It reads the focused control's corner radius, so the ring follows rounded buttons, rows and fields. This reverses the earlier ruling that focus uses the system accent.

On Windows 11 `WindowChrome` tints each window's native caption and border to `Base` and its caption text to `Fg` through `DwmSetWindowAttribute`, when the window opens and when the theme changes. Other systems keep their native caption. The brand kit's `plico.ico` is the executable's icon and every window's icon.

Dialogs are separate windows with the `dialog` class: raised, a 20 px heading, 15 px body text, and a footer under a hairline with the actions on the right and the primary last. `DialogLayout` builds the dialogs written in code in the same shape. Every default button is primary.

**Consequences.** Names, types and plain-text button content are unchanged, so the window tests and the native journey drive the same controls. The native dark check waits for the dark `Base`, RGB 11,11,12, because the main window is now the desk. Menus and tooltips have no drop shadow: Avalonia's Windows popups are transparent windows sized to their content, so a shadow would be clipped unless the menu moved away from its anchor. They keep the shadow's 1 px ring as a hairline. Fluent draws menu shortcuts as text, so they use the keycap's type rather than a drawn keycap.

**Wave 1, the shell.** The window is the desk and the workspace one sheet on it. The sidebar is Onda's 252 px from 1240 px, so at 1280 × 800 the page column is 459 px; the native fit-width step therefore runs at 1280 × 700, where a letter page fitted to its width is taller than the desk. The intake controls (intake folder, watched scans, watch, resume and catch-up, catch up on open, phone inbox, recognition language, engine and orientation, back up) moved from the sidebar into Settings under the same names and types; the sidebar ends in a status card that reports the watch, the language, the intake destination or the work in progress and opens the setting or report that explains it. The permanent status bar became an ink toast over the page canvas, kept clear of Mark reviewed. A toast carries one action, the latest offer, and only with the message that follows the offer, so an unrelated message never carries an older Undo; Ctrl+Z and the palette keep every offer. The status message is raised on every assignment so a repeated message is a new toast. Undo itself, inline editing in the filing card and settings as in-window pages are left for later waves.

**Wave 1, after the design review.** Text that does not fit is a defect, so the shell gives way in a fixed order rather than cutting words. A toast's words come from the message of record: `Status` stays the full sentence (the log, the live region, what tests read), and the toast shows a short title with no full stop and a body, chosen by the call site for the common messages ("Marked reviewed" over the document's title, "Backup saved" over the count and a friendly path) and otherwise taken from the first sentence and the rest, with known folders written as friendly paths. Toast words wrap and are never trimmed. A sidebar place whose name is long in a language gets a short label for the row (catalog keys ending in `Place`, which may repeat a place's English and so stay out of the English lookup); the full name is the tooltip and the accessible name. The queue's count line is laid out by `CountLinePanel`: the count first and whole, the sort choice in what is left, trimming its own label. Dates go through `DisplayDates`, in the interface's language. Number fields replace Fluent's spinner template with one frame, and the tag suggestions popover keeps a transparent margin inside its overlay popup so its shadow is not clipped by the popup's bounds. The library opening is a quiet message: it is the message of record but raises no toast, since the window itself shows it.

**Wave 2, Undo and filing in place.** Undo has one offer at a time (`UndoOffer`: a title, a body and a revert that goes through `InboxLibrary`). The action it reverses makes it and its toast names it; a later undoable action replaces it, and any other change Plico makes to a document retires it, so Ctrl+Z and the palette reach only the latest change and do nothing without an offer. This replaces wave 1's rule that Ctrl+Z and the palette keep every offer. Retiring is stricter than the brief's "a change to the affected documents": a change to any document retires the offer, because an Undo that skipped over a later change would reverse something the person is no longer looking at. Reading (searching, the queue, exports, imports) leaves it. Review, batch review, Trash, the single-document title, date and tag edits, accepted suggestions and a tag added to a selection are undoable; the other document changes call `RetireUndo` where they write. The filing card's title, date and tags are edited in place: the heading is the title's field, the date a text field that reads and writes the interface's own format with a calendar popover drawn in the window, and the tag field adds on one Enter. The single-document title and date dialogs are gone; several selected documents keep the date dialog. A results reload no longer hides the card for the moment the list is empty, which used to drop the keyboard focus of whatever control in the card had it.

**Wave 2, search, the first run, the voice and the polish.** A search that cannot run no longer replaces the results: `ShowQueryIssue` keeps the last valid page, the open document and the count, and the correction is a translated line under the search field, so a mistake while typing never empties the queue or the card and never lands in the 84 px strip. The search syntax lives in a translated Search tips flyout instead of an English tooltip. Until a library has its first document, the welcome hero carries the two ways in and the toolbar and the sidebar's saved searches and tags wait (`LibraryHasDocuments`). Scroll bars are drawn only under the pointer for every `ScrollViewer`, not only the sidebar's, so no in-flow edge carries a permanent thumb. Messages about a number of documents go through `Counted`, which picks a catalog row for one and one for several, because French agrees with the number where English does not. Dates are written and read one way (`DisplayDates`, "22 Nov 2026 at 12:13"), dialogs included, and words that name the machine come from `PlatformText`. The viewer bar's two groups are laid out by `ViewerBarPanel`, which keeps them on one row when they fit and otherwise moves the zoom group to a second row, so no two buttons overlap in any language.

**Wave 2, after the review.** Two reviews of wave 2 found where its pieces met. A search that cannot run keeps the results it replaced, so every reload after a change now reads the filter that found them (`_shownFilter`), and the correction floats over the sheet under the field instead of growing the toolbar, held back while a filter is being typed. The in-place fields save once, whatever comes next: Ctrl+Z in a field with nothing new typed is Plico's Undo, a save caused by a click that took the keyboard reloads after that click, the toast's Undo does not take the keyboard, and the title, date and tag fields stay open and save while Plico works in the background, which reverses wave 1's rule that the whole card waits for work to finish. A typed date needs the day, the month and a four-digit year. Fluent sets a text field's placeholder to half opacity inside its template, beyond a style's reach, so `FieldPlaceholder` sets it to full opacity when the template is applied; the placeholder is then the contract's Fg3. Avalonia's calendar names months and days in the thread's culture, so the window lends it the interface's culture while it is open. The first run keys off whether the library has had a document (present, trashed or unavailable), read in Plico.Desktop so Plico.Core stays unchanged.
